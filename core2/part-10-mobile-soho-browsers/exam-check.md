# Exam check: Securing Mobile Devices, SOHO Networks and Browsers

Cover the answers and try each one out loud first.

**1.** A manager leaves a company phone on a train. It holds client emails. What should the company do to protect the data?
<details><summary>Answer</summary>Remote wipe the phone using MDM. Why: a remote wipe erases a lost phone from far away. Keep a remote backup so nothing is lost.</details>

**2.** A small office has a brand new router that still uses the factory username and password. What is the most important first step?
<details><summary>Answer</summary>Change the default administrator password. Why: factory passwords are often listed publicly, so anyone can try them. Update the firmware next.</details>

**3.** A user downloads an installer from a random website. How can you check the file is genuine?
<details><summary>Answer</summary>Compare its hash with the one the maker publishes. Why: a hash is a fingerprint of the file. If yours matches, the file hasn't been changed.</details>

## More practice (written for this kit)

**4.** An owner hides the SSID and says the network is now secure. What is the real protection?
<details><summary>Answer</summary>Encryption, WPA3 or WPA2 with AES. Hiding the name only hides it from the list.</details>

**5.** Visitors need Wi-Fi but must not reach the office computers. What do you set up?
<details><summary>Answer</summary>A guest network (guest access), separate from the main network.</details>

**6.** Which screen lock gives no real security?
<details><summary>Answer</summary>Swipe.</details>

**7.** A public web server must be reachable from the internet while protecting the inside network. Where does it go?
<details><summary>Answer</summary>In a screened subnet (formerly DMZ).</details>

**8.** A user opens a website and the browser shows a certificate warning. What do they do?
<details><summary>Answer</summary>Stop and don't proceed. The site may be fake or the certificate invalid.</details>
